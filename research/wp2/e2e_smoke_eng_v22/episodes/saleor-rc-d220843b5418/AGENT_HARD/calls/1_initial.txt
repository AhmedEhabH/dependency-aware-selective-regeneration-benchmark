Looking at the issue description about preventing circular payload generation when listing shipping methods for checkout, I need to examine the code flow that could cause circular references.

The problem appears to be in the `get_all_shipping_methods` method in `CheckoutInfo` class where there's a potential circular reference when calling external shipping methods that might trigger webhook events which could generate payloads that reference the checkout again.

Let me analyze the relevant code sections:

1. In `saleor/checkout/fetch.py`, the `get_all_shipping_methods` method calls `get_external_shipping_methods_for_checkout_info` which triggers `manager.list_shipping_methods_for_checkout`
2. This could potentially cause circular payload generation if the webhook payload generation tries to access shipping methods again

The fix should prevent reentrancy in the shipping method calculation by tracking if we're already in the process of calculating shipping methods.
